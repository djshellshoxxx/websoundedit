# WebSoundEdit 1.0.0-beta.2

This update repairs the publication workflow, adds three editing tools and a noise gate, and expands presets, themes, scripting, batch audio, device controls and the live signal display. One responsive workbench serves desktop, tablet and phone.

## New editing tools

- **Insert silence:** insert an exact duration at a chosen position in a clip. All channels remain aligned; Undo restores the original audio.
- **Zero crossing:** adjust selection boundaries to nearby shared zero crossings within a bounded search window. A boundary stays in place when a suitable crossing is unavailable.
- **Extract channels:** create named mono tracks from a stereo or surround clip for independent editing. The source remains intact and extracted tracks start muted, avoiding doubled playback. Unmute the tracks you want to use.
- **Noise gate:** reduce quiet material using threshold, attack, hold and release controls. Stereo-linked and independent-channel operation use the same implementation for selection processing and live effects.

## Thirty-two audio presets

The searchable **Audio presets** catalog covers Cleanup, Vocals, Instruments, Compression, Limiting, Mastering and Creative recipes. Preview, audition and A/B operate on the selected interval/channels; Apply commits one undoable edit without changing duration.

Recipes include auto limiter, clipped-peak repair, two de-essers, vocal presence, bass/drum/acoustic/piano shaping, four compression choices, four limiting choices, four mastering starting points, and telephone/tape/chorus/pulse textures. The same immutable recipes are available to scripts and batches with `effect.preset`.

Vocal isolation, instrumental isolation and vocal removal use stereo center/side math. They require an original stereo clip with both channels selected and are not AI stem separation. Centered instruments can follow centered vocals; panned vocals/reverb can remain; side-only instrumental output cancels when summed to mono. Repair reconstructs only short flat clipped peaks with usable shoulders, not arbitrary distortion. Auto limiter uses bounded RMS gain and a sample-peak ceiling. No recipe claims LUFS or oversampled true-peak compliance.

## Themes and live visualization

Six added palettes—**Graphite, Ocean, Aurora, Ember, Paper and High contrast**—join **Studio, Daylight, Midnight and Terminal**. The ten-theme gallery, Options and quick selector stay synchronized without changing project audio.

The bottom **See what you hear** panel starts in full-color Waveform mode and also offers Waterfall and Spectrogram. It follows program output after live effects or an already-active input. Waveforms keep channels separate; frequency views combine channel powers so antiphase stereo stays visible. Freeze preserves the picture while audio continues. Reduced-motion settings pause animation, and hidden/offscreen views suspend analysis. The display has bounded history and does not acquire input permissions by itself.

## Scripting and batch audio

- **Thirty-five data tools:** seeded random numbers and choices, arrays/ranges/copying/shuffling, math and text helpers complement nested `repeat`, `while` and `for…of`, conditions, reassignment, `break` and `continue`.
- **Six editable examples:** batch WAV normalization, WAV/FLAC/MP3 copies, repeatable variations, a seeded sound bank, conditional cleanup and an array workbench.
- **Run results:** inspect returned variables and the last result, or download the complete retained result JSON. Long visual previews are explicitly shortened.
- **Quick batch conversion:** choose WAV, MP3, FLAC, Ogg Vorbis, Opus, M4A/AAC, raw AAC, AIFF, ALAC or WMA v2, an optional audio preset and optional −1 dBFS sample-peak normalization. Inspect the generated script before running.
- **Isolated file processing:** inputs run sequentially in temporary sessions; the original project and script draft are restored after completion or cancellation. Per-file outcomes and completed exports remain available. Collected outputs can be downloaded as a ZIP; all existing input, PCM and artifact bounds remain in force.

The quick converter preserves source channels using raw clip export at the current project sample rate. Codec layout limits still apply. A fixed seed repeats per batch file; a filename seed gives reproducible per-file variation. The interpreter does not evaluate JavaScript or read unsupplied paths. [Scripting reference and examples](../SCRIPTING.md).

## Audio interfaces and device controls

Input/output Options now expose **Rescan devices**, the available output-permission picker, actual audio-engine/input sample rates, reported capture processing and browser latency estimates. Choose input channels, start capture explicitly, and configure monitoring separately. Microphones, built-in cards and USB interfaces use the browser/operating-system audio route; exclusive native-driver or hardware-buffer control is outside the web API. Reported latency is not a measured hardware round trip.

## Mobile workbench

The same URL adapts to phones and tablets. Phone waveforms use the available width, primary controls have larger touch targets, input text stays readable, and Options, Help, macros and export dialogs adapt to narrow screens. Mouse hover and keyboard guidance remain available; touch interactions do not leave hover tips over the controls.

Cancelled waveform gestures restore temporary clip positions and the cursor. A second pointer cannot complete another pointer's drag.

## Reliability and publication

- Clearing a recovery snapshot invalidates pending serialization and waits for older writes to finish before removing the snapshot.
- Pages deployment and wiki/prerelease publication have separate job results. The prerelease still requires successful application verification and wiki publication.
- Release names and assets follow `package.json`; build and source identifiers must match. Existing tags and published assets cannot be replaced by a retry.
- Browser verification covers Chromium, Firefox and WebKit plus Android/iPhone viewport and touch emulation. Codec, editing, real audio-worklet and repeated-operation checks run against the built application.
- Linux headless verification supplies a clocked PulseAudio virtual output for real browser audio graphs. It preserves the native PCM/worklet assertions and records backend diagnostics; physical audio hardware is a separate check.

## Verification and limits

See the workflow on the exact commit for executed results and retained screenshots. Browser engines and emulated mobile viewports do not verify physical MIDI controllers, device-specific latency or a real surround speaker setup. Device selection, system audio capture and streaming file export are capability-dependent and remain explicit in Options.

The application remains a static, local-processing editor. No new hosted audio service is required. The existing project/resource limits and explicit confirmation of capture permissions remain in place.
